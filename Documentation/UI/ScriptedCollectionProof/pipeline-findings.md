# Pipeline findings from reflected collections

The [focused fresh gate](verification.md) passed 32 selected tests with 33 inspected captures. The findings distinguish delivered and observed behavior from proposed next work; the earlier failed attempts remain in the receipt.

| Finding | Evidence and effect | Current scope |
| --- | --- | --- |
| Native pure reorder did not publish | A fresh headless test failed exactly the requested-order, collection-revision and notification assertions. Payload-changing updates worked, masking the order-only path. | Minimal native ordered-pointer comparison added; final flat/batch/nested and repeat/table siblings pass. |
| Script collection bridge was missing | Native collections and repeated templates existed, but the reflected session exposed scalar declarations only. | General flat schema/record/item-action adapter and the actual registered AngelScript consumer pass the focused gate. |
| Bitmap content is awkward to author from script | The shell can import and retain a UTexture2D, but the flat collection bridge cannot yet declare native Image fields or a resource catalog. | Orbital backdrop uses the existing UMG shell path. Row thumbnails from the reference are explicitly absent. |
| Rich models remain native | Native children, Image and FloatSeries are not represented by the five-kind reflected wrapper. | Nested/tree and graphic-resource authoring need focused bridge work rather than a new parser. |
| Model publication is distinct from widget refresh | Repeat subscribes to the model and stages later topology refresh. A model setter cannot promise successful synchronous realization. | Keep atomic native publication, staged presenter refresh and stale-callback rejection; document the phase boundary. |
| Ordinary row buttons are recreated on refresh | Keyed item roots, search controls and custom widgets retain identity, but the presenter constructs ordinary buttons again, including for pure reorder. The first gate exposed an unsupported button-retention assertion. | Current-button actions are tested separately from retained item identity. Button retention and controller focus continuity need a presenter proof. |
| Static preflight missed native style admission | The contract matched every ID/class, but native admission rejected padding on a text leaf and then fixed dimensions on the region root. | Padding belongs to a container and the UMG shell owns root dimensions. Role applicability and root-mount constraints need explicit preflight; identity checks alone cannot replace native admission. |
| Native text measurement must drive fixed row budgets | The mounted screen exposed an overflowing detail panel and several rows shorter than their actual font metrics. Flex growth alone did not allow the intrinsic panel to shrink. | Explicit panel shrink and measured height budgets correct the source. Native bounds and pixel inspection remain required; a browser-style expectation or mock image is insufficient. |
| Multi-value screen policy is not one transaction | Selected-detail text values are set independently after the script accepts a full-record replacement. | This single-thread fixture does not prove atomic observation across collections and scalar bindings. |
| Repeated-item controller navigation is unproven | The gym uses native mouse controls and stable keys. Existing reflected focus helpers address ordinary root buttons by ID. | A focus API with item identity and an owning input context needs its own production proof. |
| Development file paths are still the lookup convention | The gym resolves fonts, HTML/CSS and backdrop through ProjectDir and EngineContentDir; NonUFS declarations stage its resources. | Packaging and relocated installed-plugin lookup remain unverified. |

The next bounded graphics proof should expose existing native image resources to the reflected session and keyed records, then add real mission thumbnails without a screen-specific C++ host. Its acceptance criteria should include atomic catalog admission, missing/invalid resources, retained rendering lifetime after reload/release/GC, and native captures at the existing three viewport sizes. This proposal is not a claim that those capabilities are already delivered.

These findings support expanding the current HTML/CSS-to-Slate pipeline for script-created UMG. They do not justify deprecating it, nor establish complete feature or production-fidelity parity with ReactorUMG.

## Authoring and ownership decision

All hierarchy, layout, styling, bindings, actions, and state transitions must come from reviewable source code or declarative text. Do not hand-author this layout in a Widget Blueprint. Imported textures and other necessary cooked assets may be generated from source files by an import step.

The current gym [1] path uses the AngelScript `UCk_ScriptedPause_Widget` CommonUI activatable screen. It owns a reflected `UCk_UI_AuthoredSession_UE` mounted in `UCk_UI_AuthoredSurface_UE`; that surface paints the source-authored Slate descendants. The earlier native `UCk_PauseMenuProof_UE` path and its captures are retained as historical proof.

The UMG host is real, but descendants produced by the authored session remain Slate controls. The labels below distinguish host UWidgets from authored Slate elements. If later work requires every element to be an individual UWidget, that requires a separate backend decision. No per-node UMG backend is claimed here.

The editor is for running, inspecting, capturing, and validating the source-authored result. The current entry point is the CkTests "UI Authoring" gym. Monolith is an optional tool for those operations; it is not needed to generate this reference and has not been cloned or installed. Its upstream overview currently targets UE 5.7 and 5.8, so compatibility with the actual CK engine must be checked before integration. Existing UnrealToolbox build/test rules still apply.

## Intended screen

A quiet, full-screen pause menu over a dimmed landscape. One centered panel contains a pause symbol, heading, helper text, separator, and three actions. A keyboard hint sits outside the panel. Resume receives initial keyboard focus.

Exact text:

- Heading: PAUSED
- Helper: The game is paused.
- Actions, in order: Resume; Settings; Return to title
- Keyboard hint: Esc followed by Resume

There is no game title, logo, inventory, HUD, secondary page, modal, or animation system in this first reference. Settings now opens the second authored proof, documented in [SettingsMenuProof](../SettingsMenuProof/README.md). Return to title remains an observable fixture request.

## Shared button state contract

All three actions share the same state rules. Resume is amber in the image because it has focus, not because its color is permanently special.

| State | Fill | Label | Border / focus | Behavior |
| --- | --- | --- | --- | --- |
| Normal | #25333E | #F4F0E6 | #62717B, 1 unit | Available for focus/click |
| Hover | #314453 | #F4F0E6 | #E7AD4A, 1 unit | Visual feedback only; no action |
| Focused | #E7AD4A | #101A22 | Separate #FFF6DF focus outline | Enter/Space or bound Confirm invokes action |
| Pressed | #B87929 | #101A22 | Keep outline if focused | May offset label by 1 unit; no layout resize |
| Disabled | #1B2730 | #727F8A | #36424A, 1 unit; no focus outline | Excluded from navigation and activation |

State priority is disabled, then pressed, then focused, then hover, then normal. Focus is also an independent outline when pressed. Bounds, padding, and font metrics remain constant through state changes. Initial visual target is static; animation timing is deferred.

`SCkUiStyledButton` has an authored focus style and outline, and the CkTests screen targets the initial Resume button through its accepted view. Rendered focus fidelity is a separate validation requirement.

## Data and action contract

The bindings below use the names accepted by the authored resource and host. Dynamic input-method presentation is a later extension.

| Binding | Type | Owner / meaning |
| --- | --- | --- |
| PauseTitle, PauseSubtitle, PauseResume, PauseSettings, PauseReturnToTitle | FText | Stable localized keys provided by the screen/view model |
| ResumeEnabled, SettingsEnabled, ReturnEnabled | bool | View-model availability; drive button enabled state |
| resume-keycap | literal key hint | Static passive Esc legend; not derived from the live key mapping |
| InputResumeHint | FText | Separate hint label, initialized to Resume |
| ResumeRequested | action | Release this screen's pause ownership and pop the screen |
| SettingsRequested | action | Opens the authored Settings screen in the same host and records one accepted request |
| ReturnToTitleRequested | action | Initial fixture records exactly one request; later confirmation/navigation |
| Initial focus target | stable ID | `resume-button`, selected by the host from the accepted view |

The shared key-hint stays on the keyboard fixture. Tracking the active input method, deriving the key label from a remappable action, and presenting a gamepad prompt are deferred. The bound hint text is independent of the `PauseResume` button label.

Use live FText bindings rather than relying on extracting literal strings from markup. The host owns model, UObject assets, and the view's lifetime; callbacks must not keep released screens alive. This CkTests screen opts into restoring an enabled button's logical focus by stable ID on compatible reloads. Ordinary stateless buttons retain their existing focus-clears-on-reload behavior unless the owner enables this policy.

The single-player pause fixture owns a pause request and releases only what it owns. Popping this screen must not blindly clear an unrelated system's pause state. Settings opens an editable draft in the same host. Cancel returns to Pause without releasing its pause ownership. Return requests are recorded without map travel.

## Input and layout behavior

- In the shared gym selector, choose **UI Authoring** under **CkUI**. Its control panel offers **[1] Pause menu** and **[2] Settings**; the standard **H** key controls panel visibility. Opening Pause enters the existing per-player CommonUI menu layer, hides the gym panel, and gives Resume visible keyboard focus. Its Settings action opens the form in the same host; Cancel returns to Pause. Cancel from direct [2] Settings closes the preview.
- While the menu is open, Esc or Resume closes it and returns to the gym. Tab navigates the menu; when the menu is closed, Tab opens the shared gym selector.
- Tab and Shift+Tab traverse enabled actions in display order; Up/Down use the same order. Define wrapping consistently; use wrapping for this three-action fixture.
- Enter/Space activate the focused action once. Esc resumes through the same action route as Resume.
- Mouse hover and press expose the states above. Clicking activates once, and gameplay input does not leak through the screen.
- When a focused action becomes disabled, move focus to the nearest enabled action. A disabled action never dispatches.
- Closing while a key/button is held must not send a delayed click to another screen or the world.
- A gamepad smoke check can exercise Confirm/Back and focus; physical gamepad input and dynamic prompts are deferred. Two-user and two-controller ownership are later coverage, not implied by a one-player pass.

Reference logical viewport is 1920 x1080. Keep the card width capped at 680 reference units and center it; do not stretch it on ultrawide screens. Use one deliberate DPI policy, with expected conceptual scaling based on min(viewport width /1920, viewport height /1080), rather than applying an additional manual scale on top of UMG DPI scaling. Final implementation must verify the actual coordinate space.

Initial render cases: 1920 x1080, 1280 x720, and 2560 x1080. At 2560 x1080 the foreground keeps the reference size and shifts to the viewport center; only the background crops/extends. Long localized labels must remain readable, with no collision or hidden actions.

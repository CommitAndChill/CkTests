# Mass Effect 3 HUD replica

The **UI HUD: Mass Effect 3** gym station mounts a passive [authored HTML](../../../../Resources/UiAuthoring/CombatHudProof/Futuristic/CombatHudProof.ui.html) and [CSS](../../../../Resources/UiAuthoring/CombatHudProof/Futuristic/CombatHudProof.ui.css) pair in the code-created `UCk_CombatHudProof_UE` wrapper. The [replica contract](replica-contract.md) explains the original-game references, geometry and context behavior; the [machine-readable design contract](design-contract.json) inventories all 65 current IDs with native widget kind, parent, classes, typed binding properties, literal body text and computed class CSS.

Original PC combat HUD topology: upper-left power quickslots, lower-left ammunition and weapon readout with loaded text at native Slate font size 40 in a 68-logical-unit line and reserve text at font size 18 in a 28-logical-unit line, lower-center curved shield/health and two squad portraits, centered reticle and contextual objective or empty-ammo copy. Cyan holographic readouts, red weapon-ammunition accent, compact squad portrait strip and curved native vital arcs. The only runtime bitmap is squad-portraits.png (1774 × 887, two 887 × 887 UV halves). Other art is native replica-art vector drawing. The generated hud-atlas.png and old reference/capture files are historical, not runtime authorities.

The host mounts a fixed 1920 × 1080 logical surface through SafeZone and ScaleToFit. Its HUD is hit-test invisible, does not pause the world or capture gameplay focus, and letterboxes rather than stretching on ultrawide viewports. Layout coordinates are authored approximations to the cited game references. Fonts are substituted, icons and engraving are recreated, and the presentation makes no pixel-perfect claim.

The shared model is a deterministic in-memory CkTests fixture. This station starts with **50 loaded / 383 reserve** and capacity **50**; it is not a simulation of all Mass Effect 3 systems and does not mutate actual gameplay inventory, weapons or attributes. Gym keys **1–9** drive Damage, Sprint, Fire/arrow, Reload/replenish, Power/capture/spell, Restore, Reset, Low health and Context cycle. Key 9 cycles baseline → objective prompt → baseline. The empty-ammo prompt follows its own ammunition state. The authored pair is polled for compatible source reload; invalid candidates must leave the last accepted view mounted.

**Scoped native verification passed.** `UiTypography-Gate-03` selected 41 tests: 41 passed, 0 failed, 0 skipped and 0 contaminated on real D3D12/SM6. The preceding incremental C++ build succeeded. Main and independent review inspected the final native pixels at 1280 × 720, 1920 × 1080 and 2560 × 1080, including reload, ability, low-health and context states; the corrected ammo digits and ticket readouts are fully visible in those captures. Native fit assertions additionally cover those readouts; other text was inspected visually. This is focused replica and compatible UI coverage, not a repository-wide regression claim. Capture-only debug/logging settings were transient and restored; the normal project and engine settings were retained. The [native capture gallery](replica-native-gallery.md) and [capture manifest](replica-native-captures.json) show this theme; the [gate receipt](../replica-verification.md) records scope and checks. Previous `native-*.png`, `native-captures.json`, `hud-atlas.png` and generated references document the retired shared dashboard. Fonts and icons remain recreations; Battlefield terrain is procedural in the Tactical replica. Physical gamepad input, real gameplay integration and packaged execution remain unverified.

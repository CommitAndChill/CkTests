# Battlefield 4 HUD replica

The **UI HUD: Battlefield 4** gym station mounts a passive [authored HTML](../../../../Resources/UiAuthoring/CombatHudProof/Tactical/CombatHudProof.ui.html) and [CSS](../../../../Resources/UiAuthoring/CombatHudProof/Tactical/CombatHudProof.ui.css) pair in the code-created `UCk_CombatHudProof_UE` wrapper. The [replica contract](replica-contract.md) explains the original-game references, geometry and context behavior; the [machine-readable design contract](design-contract.json) inventories all 61 current IDs with native widget kind, parent, classes, typed binding properties, literal body text and computed class CSS.

PC Normal Conquest topology: lower-left flags, team tickets, timer, map and squad list; lower-right weapon/ammunition, grenade and health; sparse central objective cue, a separate capture overlay near y=738 and optional upper-right kill feed. White/grey readouts with friendly cyan, opposing orange and squad green; no permanent health or reload progress panel. The minimap is a deterministic native vector street grid, not Battlefield 4 terrain or live level data. All graphics are native replica-art vectors; old atlas/reference/capture files remain historical.

The host mounts a fixed 1920 × 1080 logical surface through SafeZone and ScaleToFit. Its HUD is hit-test invisible, does not pause the world or capture gameplay focus, and letterboxes rather than stretching on ultrawide viewports. Layout coordinates are authored approximations to the cited game references. Fonts are substituted, icons and engraving are recreated, and the presentation makes no pixel-perfect claim.

The shared model is a deterministic in-memory CkTests fixture. This station starts with **31 loaded / 97 reserve** and capacity **31**; it is not a simulation of all Battlefield 4 systems and does not mutate actual gameplay inventory, weapons or attributes. Gym keys **1–9** drive Damage, Sprint, Fire/arrow, Reload/replenish, Power/capture/spell, Restore, Reset, Low health and Context cycle. Key 9 cycles baseline → capture prompt → kill feed. Capture and kill-feed nodes collapse outside their respective states. The authored pair is polled for compatible source reload; invalid candidates must leave the last accepted view mounted.

**Scoped native verification passed.** `UiTypography-Gate-03` selected 41 tests: 41 passed, 0 failed, 0 skipped and 0 contaminated on real D3D12/SM6. The preceding incremental C++ build succeeded. Main and independent review inspected the final native pixels at 1280 × 720, 1920 × 1080 and 2560 × 1080, including reload, ability, low-health and context states; the corrected ammo digits and ticket readouts are fully visible in those captures. Native fit assertions additionally cover those readouts; other text was inspected visually. This is focused replica and compatible UI coverage, not a repository-wide regression claim. Capture-only debug/logging settings were transient and restored; the normal project and engine settings were retained. The [native capture gallery](replica-native-gallery.md) and [capture manifest](replica-native-captures.json) show this theme; the [gate receipt](../replica-verification.md) records scope and checks. Previous `native-*.png`, `native-captures.json`, `hud-atlas.png` and generated references document the retired shared dashboard. Fonts and icons remain recreations; Battlefield terrain is procedural in the Tactical replica. Physical gamepad input, real gameplay integration and packaged execution remain unverified.

# Pipeline findings and limits

The existing HTML/CSS-to-Slate pipeline can drive this in-game UMG composition through code. The gym uses the same retained session, source admission, mount, reload, and action routing as the earlier proofs. HTML supplies hierarchy; CSS supplies dimensions, color, alignment, font families, opacity, and control styling; AngelScript supplies data, artwork, and behavior. No per-widget Blueprint graph or editor authoring is needed for this fixture.

This proof exposed capability gaps and led to reusable native extensions:

| Need from reference | Pipeline addition | Current evidence |
| --- | --- | --- |
| Red and violet potion-like resource orbs | `<hud-orb>` binds a value, liquid image, and frame image; native renderer clips liquid vertically and smooths the transition | Focused PIE and 720p/1080p/1350p captures show live artwork in circular frames |
| Spell artwork with graphical timers | `<hud-ability>` binds artwork and cooldown; native renderer draws a dark shade and progress rim | Six separate cooldown bindings exercised in the gym |
| Illustrated wheel options | Reflected collection `Image` field retains a texture brush and checks invalid/no-op replacements atomically; radial selector reads per-record image | Collection-image roundtrip/rejection test passed; eight icon images appear in the wheel |
| Translucent segmented wheel with exact labels | `-ck-radial-fantasy-mode` adds wedge, spokes, ring, external labels, and icon painting; radial font-family resolves the admitted authored font | Focused PIE and real-renderer captures passed |
| Centered, faint key hints | Authored keycap containers with intrinsic-width text; translucent RGBA CSS color | Latest captures show smaller, centered labels without fully opaque blocks |

The user's hotbar observation exposed a separate **composition limit**. The six spells already use a nested horizontal `row` of per-spell `column` widgets, so flex layout is doing its job. Their borders, however, are baked into one large `ornamental-hud-frame.png` image behind the row. Layout knows only that image's rectangle; it cannot infer the six transparent apertures inside it. The earlier art row sat above those apertures. We matched the row's width, padding, gap, tile size, and vertical placement to the image, and the latest captures show the tiles in the openings. This is authored coordinate matching, not a reusable constraint between image features and child slots. For a production HUD, use six individually composed slot frames or add explicit slot metadata/anchors to the art asset so slot geometry and content share one source of truth. A plain nested horizontal box cannot discover raster openings on its own.

Text backgrounds also exposed a grammar limit: the current `<text>` styling does not provide a text-align property for glyph alignment inside a fixed-width text widget. `horizontal-align` positions the widget in its parent. Removing the text width lets the parent center its intrinsic text widget. Ordinary `<button>` supports `-ck-button-text-align` and `-ck-button-content-vertical-align`. The container workaround is adequate here, but a true text alignment property would be useful for localized key hints and dynamic labels.

Other limits remain: the minimap, party list, quest, clock, and chat are illustrative; the reference game art and proprietary font were not copied; the 1920×1080 fixed canvas needs safe-zone, aspect-ratio, and type-size rules for shipping; live gameplay adapters and cooked resource packaging are unproven. The current wheel and generated art are visually related to the reference, not pixel-matched. The source validator checks IDs, classes, and selector shape but leaves declarations, bindings, and rendering to runtime admission and tests. DX12 rendered testing remains blocked by a startup shader-frequency assertion; the cause is not established.

Failure behavior remains atomic where it matters: the collection image adapter rejects invalid textures without publishing a partial collection, preserves the previous brush on no-op records, and retains valid texture resources. The gym releases its session on required startup failure and on shutdown. Its invalid-source action verifies that a rejected document does not replace the admitted live UI. The final wide run's three non-HUD failures (`PauseMenuProof.GymSelector.PIE`, `ScriptedCollection.PIE`, `ScriptingCard.PIE`) need isolated triage before any repository-wide regression claim; the preceding wide run had a different set of non-HUD failures.

# Journal pipeline findings

This exercise measures code-driven UI creation and the deficiencies exposed by reproducing a specific game screen. The [focused native gate](verification.md) passed 26 tests, with 11 inspected screenshots. It proves that this UMG fixture can be created and controlled entirely from source; several visual resources and lifecycle details still require C++ beyond HTML/CSS.

| Requirement | Implementation and evidence boundary | Pipeline consequence |
| --- | --- | --- |
| Complete code-created UMG screen | UOverlay → USafeZone → UScaleBox → USizeBox → authored surface; gym/controller registration in AngelScript. Production registry travel and host ownership passed PIE checks. | The tested screen is created and controlled from source without a WBP. The native host and lifecycle remain separate from authored layout. |
| Centered, equally spaced header rail | Added shared `-ck-tabs-header-width` and `-ck-tabs-header-align` with bounded validation and retained updates. Native geometry/reload tests extended. | A concrete reusable HTML/CSS style gap is addressed; natural-width, left-aligned defaults remain compatible. |
| Transparent list viewports | The first real-RHI captures showed opaque black rectangles even though row backgrounds were transparent. Added shared `-ck-tree-background`, independently of row styling, with passing retained native paint/rejection/default-restoration checks. | The viewport itself was not styleable from source. The journal now authors transparent viewports; omission restores the engine default. The native tree owns its brush even when retained independently. |
| Independent quest/objective selection and tracking | Existing native tree collections and display row templates; stable model keys; host maps Enter to a quest mutation. Native Down/Enter, separate miscellaneous objectives and virtualized scrolling passed. | Separate native controls can bind to code models without a bespoke Slate list layout. Gameplay semantics still belong in the model/host. |
| Selection after collection updates | The first native test found that immediate `TrySelectKey` can run before the tree refreshes its projection or inside its selection notification. Shared `TryRequestSelectKey` now admits a stable-key request and applies it after native refresh settles, with pending/applied/rejected status. Native tests cover latest-request wins, callback reentry, notification policy, filtered/removed targets, user cancellation and reload. The journal's post-tick scheduler is removed. | Callers can publish collection data and request selection through the shared control. Invalid admission preserves accepted work; failed application leaves surviving selection intact. Requests do not automatically expand ancestors or scroll the selected item into view. |
| Long data and text | Fixed reference composition plus native tree viewports; bounded title ellipsis and wrapped summaries/objectives. 130 quest fixtures, 128 displayed quest/group keys, fewer realized rows, and physical scrolling to the last quest passed. Captures cover three viewport sizes. | Native typography and realized row bounds are part of acceptance; parser acceptance alone cannot catch clipping. Partially visible rows at scroll-viewport edges are normal clipping, separate from oversized text inside rows. |
| Variable-height virtualized rows | Native trees currently use one authored `row-height` and a fixed-height cell box; this journal uses 52/58 units. | Arbitrarily long objective text does not become a taller row automatically. Current fixtures and realized-row checks establish bounded copy only. Per-row wrapping/height and long localized text need a separate shared-control extension and proof. |
| Condensed, licensed typography | The shared CkWidgets helper admits all declared primary/fallback bytes before constructing an owned inline composite. The Engine-free catalog supplies immutable snapshots; CSS selects `journal-ui` on 14 journal classes. Native tests cover malformed siblings, effective Regular/Bold selection, rejected reloads, nested views, retained bytes/assets after GC and registered fallback selection. Fresh journal captures render condensed copy and diamond/triangle markers. | Family selection is now authored in CSS and bespoke composite construction is removed. Unknown names/missing required faces reject before widget factories. File staging and licenses remain the resource owner's responsibility; reflected declarations and packaged acceptance are not yet established. No inheritance, font lists, quotes, URL/file imports, or new control schemas are implied. |
| Skyrim frame/ornament geometry | Retained, passive `journal-art` leaves paint recreated lines and diamonds; HTML/CSS places and sizes them. | Layout remains authored, but decorative vector paths are C++. There is no general source-authored path/ornament primitive in this proof. |
| Scrollbar/expander/focus chrome | Existing native trees expose viewport and row backgrounds, hover/selection and accent, with engine scrollbar/indent/focus behavior. The first captures show the engine's blue keyboard-focus outline. | Exact capped Skyrim scrollbars and full native chrome styling remain a fidelity limit. Keyboard focus stays visible; source-authored focus styling remains a gap. |
| Source reload and teardown | Required structure is validated before reload; accepted root/tree/tab identities, selection and scroll survive compatible reload. Owner release cancels deferred work and retires externally held trees. A real authored context menu triggers focus reentry that diagnostic-reloads/removes two trees during teardown; both retained trees remain inert. | Agent iteration can stay in source with atomic rejection and callback revocation. Teardown snapshots all owned interactions before focus callbacks can change the retained structure. These checks establish the tested reload/lifetime paths. |
| CommonUI focus and transitions | The host accepts its own CommonUI focus target only while its exact layer is active. Native J/Escape close, external-pause preservation and natural close-transition completion passed. | Code-created menus must account for CommonUI's focus and deferred removal, not just the authored root. A reusable host would consolidate that lifecycle contract. |
| Host and binding setup | The journal supplies a dedicated C++ host for typed bindings, CommonUI layer admission, input, focus, pause and reload, alongside its AngelScript gym. | The shared scalar scripting facade is now proven separately in the [scripted card](../ScriptingCardProof/verification.md). The journal's collections, native art/resources and CommonUI lifecycle still require adapters; its host has not been migrated. |
| In-game quest/map behavior | Fixture tracks quests and completes objectives; map shortcut supplies a fixture response. | No real quest backend, compass markers, world map, persistence, packaged game or physical controller acceptance is established. |

The evidence supports continuing the CK pipeline. This proof added three shared CSS properties and kept the whole screen under source control. Its follow-up moved deferred keyed selection into the shared native tree and removed about 100 lines of journal-specific scheduling. The font follow-up replaces bespoke composite setup with a shared resource bridge and named CSS family selection. It still leaves substantial host/binding setup that HTML/CSS alone cannot express. It does not establish a need to add ReactorUMG or deprecate HTML/CSS. The next changes should reduce repeated authoring code across multiple screens and receive their own focused proof.

The scalar scripting boundary has passed a separate [11-test focused Editor gate](../ScriptingCardProof/verification.md), with five inspected card captures. The next bounded exercise should migrate a small existing menu and measure host-code removal while preserving focus, held-input release and pause ownership. Shared native font/fallback registration remains verified by the earlier 26-test journal/font gate. The [font and scripting inventory](../font-authoring-gap.md) and [scripting plan](../scripting-authoring-plan.md) distinguish that evidence from remaining collection/tree bindings, reflected font resources, custom factories, polling, multi-value transactions, reusable menu ownership and packaged lookup. Source-authored decorative primitives and focus/scrollbar styling would reduce fixture-specific art and improve fidelity. Variable-height virtualized rows need their own long-copy and localization exercise; this journal's fixed-height fixtures are not sufficient evidence for that capability.

Existing HTML/CSS can reload while the gym runs. Adding a missing native control capability changes C++ and requires an incremental build and fresh native verification. This distinction matters for agent iteration: supplying reusable primitives once is more valuable than repeatedly building a bespoke host for each attractive screen.

# Skyrim quest journal reference breakdown

This proof recreates the original *Skyrim* PC quest journal as a code-created UMG host with an authored HTML/CSS view. It is a UI authoring and native-control proof with fixture quests, not a game journal or a new quest backend. Keep the source's sparse chrome and hierarchy: do not add search, filters, tabs below the header, progress cards, explanatory tooltips, or gym controls to the replica itself. Gym shortcuts can live outside the journal.

## Reference and inspection boundary

- [Official PC manual, printed page 10 / PDF page index 6](https://cdn.akamai.steamstatic.com/steam/apps/72850/manuals/skyrim_gfw_manual-07.pdf?t=1647357402): text inspected through the PDF web extraction. It says `J` enters the journal; its top headers reach Quests, Stats and System; `Enter` toggles a selected quest active; `M` shows the target on the map; and Miscellaneous groups special objectives. The manual contains journal screenshots, but its pixels did not render in this task's browser/PDF tools. [Bethesda-hosted PC manual](https://assets.ctfassets.net/rporu91m20dc/2VLVwistnGywCKuO8CUwCE/12180919f2102d4253bb034b0bb4b632/manual_skyrim-le_pc_en-int.pdf) is an alternate official source.
- [Original-era 2012 article](https://thenocturnalrambler.blogspot.com/2012/02/skyrim-actually-kinda-sucks.html) and its [direct Miscellaneous journal image](https://4.bp.blogspot.com/-OnrY9WaMLms/T0WHwU3-1fI/AAAAAAAABPY/JlUAiiywJrc/s1600/Skyrimmiscellaneousquests.jpg): the main task visually inspected the actual image in the in-app browser, displayed at 1280 × 720 from a 1600 × 900 source. The observations below come from that image, not from the article's opinions. The source is an original-era gameplay capture; its background and content are fixture details, not required asset copies.

The screenshot is the visual anchor for the Quests/Miscellaneous state. The manual is the primary interaction reference. Approximate coordinates below are observations at the browser's 1280 × 720 display size, not verified original-game layout constants. The 1920 × 1080 dimensions are a proposed scale-by-1.5 logical composition for our capture target. Typography, ornaments, game scene, and precise pixels require native capture comparison before claiming fidelity.

The source favors tall, condensed, high-contrast white uppercase headings and quest names, with softer gray objective copy. It does not read as a standard rounded-card dashboard. The ornament, diamond bullet, selection pointer, header chevrons, and capped scrollbar are small but recognizable fidelity cues; replacing them with default Slate glyphs or generic boxes would make the proof visually misleading. Use an appropriately licensed/recreated font and ornament assets. Do not imply that the screenshot grants a license to copy game art.

## Interaction states to prove

1. Open on **Quests** with a selected ordinary quest: left list selection and active-track marker are separate concepts; right side has title, ornament, summary and objectives. `Enter` toggles active status without changing the selected quest. The manual says an active quest gains world/compass/map targets; this fixture only needs observable journal state, not gameplay target integration.
2. Select **Miscellaneous**: keep it in the left list and show its individual objective rows in the right pane with hollow diamond markers and scrolling. The manual describes it as a category of special objectives. Its detail area is not a synthetic searchable database or a new filter screen.
3. Navigate the header to **General Stats** and **System** so the active-header treatment and focus path are real. Fixture content may be bounded; preserve the three source labels and do not invent extra replica tabs. `M` should use a fixture/show-on-map response unless a real map exists; do not claim world-map integration.
4. Long quest and Miscellaneous data should scroll without text overlap, lost selection, or a detached scrollbar. Keyboard/controller focus and pointer activation must share the same selection/active state; closing must release focus and any retained UI interactions.

## Pipeline stress and likely fidelity blockers to measure

- **Typography:** authored font family/weight/condensed metrics, baseline, tracking, uppercase text fit and muted/bright states must survive HTML/CSS → Yoga/Slate text → UMG. A default engine font is not a faithful substitute. Verify long quest names and wrapped summary/objectives at actual RHI capture sizes.
- **Header and ornaments:** the thin framed rail, tiny active chevrons, symmetric heading ornament, hollow bullets, chamfered edge and capped scrollbar need either supported authored primitives/images or narrowly scoped registered native drawing. If a CSS property is unsupported, surface a source validation failure; do not silently approximate it with default focus outlines.
- **List semantics:** dense right-aligned quest rows, active-vs-selected indicators, and Miscellaneous objective expansion need stable keyed rows and a real scroll viewport. Check whether the current tree/collection controls expose row slots, expander marks, selection focus, scrollbar skinning and source-reload state retention. Add only the missing general authoring capability required by the reference.
- **Compositing and host:** a code-created `SafeZone` + `ScaleBox` should fit one 1920 × 1080 logical frame into 1280 × 720 and 2560 × 1080 without clipping or stretching fonts/ornaments nonuniformly. Observe scene dim and smoke/translucency through the real viewport; no WBP is required. Distinguish engine focus chrome from source-authored selection marks.

Capture at minimum ordinary quest and Miscellaneous at 1920 × 1080; selected-vs-active quest, scrolled objective list, General Stats and System header, and closed cleanup. Repeat the main quest/Miscellaneous view at 1280 × 720 and 2560 × 1080 for proportional fit. Treat source-pixel geometry as a reference to compare, not an assertion that browser scaling or a different gym backdrop matches Skyrim exactly.
